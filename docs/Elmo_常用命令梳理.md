# Elmo 常用命令梳理（基于本工程已实现代码）

> 结论先说：目前**只能 100% 确认“工程里已经在用”的命令/对象字典索引**；你关心的“抱闸/急停/快速停/故障复位”等，在现有源码里没有直接出现，需要补齐官方手册（或抓包/型号信息）才能给出确定的命令名与参数。

## 1. 工程现状：两种后端

- RS232：SimplIQ ASCII 指令（见 Core/src/elmo/elmo_rs232.c）
- CAN：CANopen SDO（见 Core/src/elmo/elmo_can.c）

并通过 `ElmoOpsTable` 抽象成统一接口（见 Core/inc/elmo_ctrl.h、Core/src/elmo/elmo_ctrl.c）。

## 2. RS232（SimplIQ ASCII）已确认在用的指令

这些指令在工程里有完整的“下发/查询/解析”链路，因此属于**可操作**的命令集：

- `MO`：使能/去使能（工程用法：`MO=1`、`MO=0`）
- `SP`：速度给定
- `AC`：加速度给定
- `DC`：减速度给定
- `PR`：相对位置给定
- `PA`：绝对位置给定
- `BG`：触发运动（在写完 `PR/PA` 后执行）
- `PX`：位置反馈查询（工程解析：`PX=...`）
- `VX`：速度反馈查询（工程解析：`VX=...`）
- `IQ`：电流反馈查询（工程解析：`IQ=...`）
- `SO`：状态查询（工程解析：`SO=...`）
- `EC`：错误码查询（工程解析：`EC=...`）

> 备注：这些指令的“单位/量纲/允许范围/模式依赖”等，需要以 Elmo 官方命令参考为准；当前工程只体现了“用得到、能跑通”。

## 3. CAN（CANopen SDO）已确认在用的对象字典索引

工程里使用的是典型 SDO：

- 读：`0x40` Upload Request
- 写：`0x22` Download Request（一次写 4 字节，小端）

### 3.1 写入（对应“设置值/控制”）

- `0x3146 / 0`：MO（使能位）
- `0x31E3 / 0`：SP（速度给定）
- `0x3002 / 0`：AC（加速度给定）
- `0x3050 / 0`：DC（减速度给定）
- `0x3197 / 0`：PR（相对位置给定）
- `0x3186 / 0`：PA（绝对位置给定）
- `0x3020 / 1`：BG（触发运动，工程写入值为 1）

### 3.2 读取（对应“反馈/状态”）

- `0x319D / 0`：PX（位置反馈）
- `0x3239 / 0`：VX（速度反馈）
- `0x30E0 / 0`：IQ（电流反馈，工程按 float 解析）
- `0x31E2 / 0`：SO（状态字）
- `0x306A / 0`：EC（错误码）

## 4. 你关心的几个功能：目前能确定到什么程度？

### 4.1 “查询位置设置值（目标值）”

目前有两种层级：

- **MCU 侧（软件缓存）**：工程会把最后一次下发的目标值保存在 `g_elmoParam.set.abs_pos_set` / `g_elmoParam.set.rel_pos_set`，所以“查询设置值”在 MCU 内部是可直接读到的。
- **驱动器侧（从 Elmo 读回）**：
  - CAN：理论上可以对 `0x3186/0`、`0x3197/0` 发送 SDO 读请求来读回（但当前 `elmoCanProcess()` 没有解析这两个 index 的返回）。
  - RS232：是否支持 `PA`/`PR` 的读回形式（例如无参数查询）需要官方命令参考确认；当前工程没有实现这类查询。

### 4.2 抱闸（Brake）

- 通过你补充的手册 docs/MAN-SIMCR.pdf（SimplIQ Command Reference, ver 4.5）可以确认：Elmo 的抱闸属于“**数字输出映射 + 抱闸时序参数**”两部分。

**必需命令（SimplIQ ASCII / 同时也适用于 CANopen 侧的参数概念）**

- `OL[N]`：把某一路数字输出的“功能”设置为 `Brake`（手册里该功能编号为 2）。一旦输出被映射为 Brake，`OB[N]`/`OP` 对该输出不再生效。
- `BP[N]`：抱闸时序参数。
  - `BP[1]`：MO=0 后，抱闸“开始介入/动作”的延时（msec，范围 0..500）
  - `BP[2]`：抱闸“确认介入后”，再去执行电机禁能/切断的延时（msec，范围 0..500）
  - 备注：手册明确写了“brake output is always active low”，并指出在 MO 切换期间，解释器命令响应时间会被 BP[1]/BP[2] 拉长。

**可选（用于诊断/状态确认）**

- `OB[8]`：当至少一个数字输出被映射为 Brake 时，`OB[8]=1` 表示抱闸已抱紧，`OB[8]=0` 表示抱闸已释放。

**工程侧落地建议（结合你现有代码）**

- 当前工程里还没有下发 `OL[]/BP[]/OB[]` 的实现；如果你希望“软件命令控制抱闸”，需要先明确：抱闸线圈是否确实接在 Elmo 的某个数字输出上，以及用的是哪一路输出（对应 `OL[?]`）。
- 如果你更偏向硬件安全链路：抱闸通常仍建议走硬件互锁（电机去使能/安全回路），“软件配置 BP/OL”用于配合时序。

### 4.3 急停/快速停（E-Stop / Quick Stop）

- 通过 docs/MAN-SIMCR.pdf 可以确认：至少有两类“停”的手段，语义不同。

**A) 受控减速停（软件停）**

- `SD`：Stop Deceleration（停机减速度参数）。手册描述其用于“紧急情况下停止运动”的减速度基准，并且被以下情况使用：`ST` 命令/硬件 stop、PVT/PT 数据下溢、限位/abort 开关触发等。
- `ST`：Stop Motion。手册描述为：软件运动按 `SD` 设定的减速度减速到 0；不影响外部位置参考；对某些状态组合（例如 MO=0 且 UM=1）无效。

**B) 立即停止/去使能（更接近“急停效果”但要看机械安全）**

- `MO=0`：电机去使能（工程里已实现）。如果配置了抱闸（`OL[]`+`BP[]`），手册明确在 MO 过程中会按 BP 时序处理；并提到“实时 emergency disable 时，抱闸会在电机禁能瞬间动作，电机可能先 freewheel 到抱闸完全介入”。

**C) DS402 标准 Quick Stop（CANopen 主站控制）**

- 手册在 `BG` 与错误码说明中明确提到：在 “Quick stop” 状态下，`BG` 会被阻塞并返回错误；该状态由 CANopen DS402 控制字对象 `0x6040` 控制。
- 这意味着：如果你现场系统是 DS402 主站在管控状态机，单靠你现在的 SDO 写对象字典（0x31E3/0x3186/...）可能不足以完成“急停/恢复”，需要按 DS402 的状态机流程处理。

**工程侧落地建议（最简）**

- 如果你只需要“快速受控停”：优先走 `ST` + 合理的 `SD`。
- 如果你需要“立即去能停”：走 `MO=0`（必要时配合抱闸输出映射）。
- 如果你现场是 DS402：把 `0x6040` 状态机纳入控制逻辑（至少要能识别/退出 Quick stop 状态）。

**补充：停止用户程序**

- `HP`：Halt Program Execution（停用户程序但不 reset 状态；后续可用 `XC` 继续）。
- `KL`：Kill Motion and Program（停用户程序 + 并执行 `MO=0` 去使能；同样可用 `XC` 继续，但可能因电机已 off 而失败）。

## 5. 你需要补充/提供的资料（最少集）

为了把“抱闸/急停/复位/读回目标值”等补齐到可执行命令，建议你至少提供：

1) Elmo 驱动器具体型号 + 固件版本（或照片/铭牌信息）
2) （已补齐）SimplIQ Command Reference（你已提供 docs/MAN-SIMCR.pdf）
3) 如果走 CANopen 且需要 DS402：Elmo CANopen Implementation Guide / DS402 状态机相关章节（至少包含对象 0x6040 的说明）
4) （可选但很快）抓包：一段你认为“抱闸/急停/复位”操作时的 RS232/CAN 通信记录（可用于确认现场到底是 SimplIQ 直控还是 DS402 主站控）
