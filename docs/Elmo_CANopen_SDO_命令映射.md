# Elmo CANopen SDO（CoE）两字母命令映射与常用命令表

本文把你在官网找到的 **“Elmo Parameters via SDO Interface (CoE / CANopen)”** 说明，和我们从 [docs/MAN-SIMCR.pdf](docs/MAN-SIMCR.pdf)（SimplIQ Command Reference, ver 4.5）里确认到的命令语义合并，形成一份可直接对照实现/抓包验证的命令清单。

> 适用范围：Elmo 支持“Legacy 2-letter SimplIQ 命令”通过 CANopen SDO 访问的场景。

## 1. 映射规则（官网说明）

### 1.1 两字母命令 → 对象索引（Index）

对任意两字母命令 `<L1><L2>`（大写 A..Z），其对象索引定义为：

$$
\text{Index} = 0x3000 + 26\cdot(\text{ord}(L1)-65) + (\text{ord}(L2)-65)
$$

- `ord('A')=65`，`ord('B')=66` ...

例：
- `MO`：`0x3000 + 26*(M- A) + (O-A) = 0x3146`
- `SP`：`0x31E3`
- `AC`：`0x3002`

### 1.2 子索引（SubIndex）规则

官网说明的关键点：**每个两字母命令都被当作“数组命令”处理**。

- SubIndex `0`：只读，返回该命令允许的最大子索引数（数组长度/alias object）
- SubIndex `x>=1`：
  - 对数组型命令（例如 `BP[x]`、`OL[x]`、`OB[x]`），`x` 就是数组下标
  - 对“标量”命令（例如 `MO`、`SP`、`AC` 等），也以 `CMD[1]` 的形式访问

> 也就是说，**标量命令按官网规则应使用 subIndex=1**；subIndex=0 通常不是“值”。

### 1.3 本工程现状（重要提醒）

当前工程 [Core/src/elmo/elmo_can.c](Core/src/elmo/elmo_can.c) 中，对多数字段使用的是 `subIndex=0`（例如读 `PX` / 写 `SP` 等），但 `BG` 用了 `subIndex=1`。

- 这与官网说明的“标量应使用 subIndex=1”存在差异。
- 建议你用抓包或读回对照来确认：
  - 读 `MO`：分别读 `0x3146:0` 与 `0x3146:1`，看哪个返回实际使能值
  - 读 `PX`：分别读 `0x319D:0` 与 `0x319D:1`，看哪个返回实际位置计数

## 2. SDO 读写格式（结合本工程实现）

工程采用标准 SDO（8 字节）：

- 读（Upload Request）：`0x40`
- 写 4 字节（Download 4-byte）：`0x22`（小端）

注意：很多命令的数值类型不一定都是 32-bit（例如 bit-field、16-bit 等）。本工程当前实现“固定 4 字节写”，对非 32-bit 命令可能需要扩展（`0x2F/0x2B/0x23`）。

## 3. 常用命令映射表（本工程已用 + 手册补齐）

下面给出“命令 → Index/SubIndex”的对照。SubIndex 分两列：

- **官网规则**：按 1.2 的规则
- **工程当前**：按你现有代码行为（仅做对照，建议最终以实测为准）

> 记号：`Index:Sub` 例如 `0x3146:1`

### 3.3 抱闸（手册 MAN-SIMCR 确认）

> 结论：抱闸不是“单一命令”，而是 **输出映射（OL） + 抱闸时序（BP）**。

| 命令 | 含义 | Index | Sub（官网规则） | 读写 | 备注 |
|---|---|---:|---:|---|---|
| `OL[N]` | 输出逻辑/功能映射（含 Brake 功能=2） | `0x3177` | `N` | R/W | 映射为 Brake 后，OB/OP 对该输出不再生效（手册说明） |
| `BP[N]` | 抱闸时序参数（`BP[1]`,`BP[2]`） | `0x3029` | `1..2` | R/W | 手册要求 `MO=0` 才允许修改；范围 0..500ms |
| `OB[N]` | 输出位数组/状态（含 `OB[8]` 抱闸状态） | `0x316D` | `N` | R/W | 手册：`OB[8]=1` 抱闸已抱紧，`0` 释放（前提：至少一路输出映射为 Brake） |

### 3.4 停机/急停（手册 MAN-SIMCR + 官网 quick stop 说明）

| 命令 | 含义 | Index | Sub（官网规则） | 读写 | 备注 |
|---|---|---:|---:|---|---|
| `SD` | Stop Deceleration（紧急停机减速度基准） | `0x31D7` | `1` | R/W | 手册：用于 `ST`/硬件 stop/限位/abort 等触发的减速 |
| `ST` | Stop Motion（软件受控减速停） | `0x31E7` | `1`（写任意值触发，常用 1） | W | 手册：按 `SD` 减速到 0；不影响外部参考 |
| `KL` | Kill Motion and Program（停程序+`MO=0`） | `0x310F` | `1`（写任意值触发） | W | 手册：会执行 `MO=0`，后续 `XC` 续跑可能失败 |
| `HP` | Halt Program Execution（仅停程序） | `0x30C5` | `1`（写任意值触发） | W | 手册：冻结状态，不 reset；可 `XC` 继续 |
| `MO=0` | 去使能（更接近“立刻停”） | `0x3146` | `1` | W | 若启用抱闸，停机过程受 `BP[]` 影响（手册说明） |
| DS402 Quick Stop | DS402 状态机 Quick Stop | `0x6040` | n/a | R/W | 手册在 `BG`/错误码里明确提到：quick stop 状态会阻塞 `BG`；由 CAN 主站通过 `0x6040` 控制 |

### 3.5 复位/故障相关（手册 MAN-SIMCR 确认）

| 命令 | 含义 | Index | Sub（官网规则） | 读写 | 备注 |
|---|---|---:|---:|---|---|
| `RS` | Soft Reset（恢复出厂默认 + 清 volatile） | `0x31CC` | `1`（写任意值触发） | W | 手册限制：`MO=0` 且 Program not running；不会改 flash，需要 `SV` 才持久化 |
| `MF` | Motor fault（最后一次禁能原因） | `0x313D` | `1` | R | 该命令在手册中用于解释 `EC=66` 等情况；是否在你驱动上可读需实测 |

> 注意：上表 `MF` 的 Index 按公式计算得到（`M`=`12`，`F`=`5`，`0x3000+26*12+5=0x313D`）。

## 4. 给你现有工程的“最小增量建议”

如果你只想尽快把新能力接入现有 CAN SDO：

1) **先统一 subIndex 规则**：对标量尝试迁移到 `sub=1`（并保留兼容：先读/写 `sub=1`，失败再回退 `sub=0`）。
2) 增加以下命令的 SDO 封装：
   - 抱闸：`OL[N]`、`BP[1..2]`、`OB[8]`
   - 停机：`SD`、`ST`、`KL`、`HP`
   - 复位：`RS`

如果你确认现场走 DS402（有主站状态机）：
- 需要把 `0x6040/0x6041` 的状态机处理纳入控制流程，否则会遇到“Quick stop active，BG 被阻塞”等现象。

## 5. 附：快速算 Index 的小脚本

```python
def elmo_index(cmd: str) -> int:
    cmd = cmd.strip().upper()
    assert len(cmd) == 2 and cmd.isalpha()
    l1, l2 = cmd
    return 0x3000 + 26*(ord(l1) - 65) + (ord(l2) - 65)

print(hex(elmo_index('MO')))  # 0x3146
print(hex(elmo_index('BP')))  # 0x3029
```
